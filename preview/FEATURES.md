# 闪念：签名测试版交付说明

此构建是供 iPhone 导入审查与实测的测试版，**不是各项能力均已验证的正式版**。源文件为 `ShanNian.xml`，目标名称为「闪念」。Apple 签名只证明文件成功封装签名，不证明动作能运行。

软件采用 [AGPL-3.0-or-later](../LICENSE)。下载版首条「注释」说明官方版本免费开源并附仓库地址；该文字仅在编辑器中展示，不是运行时提示，也不参与 API 请求。

## 使用流程

1. **添加时配置**：导入快捷指令时依次填写 **API 协议**（`openai` 或 `anthropic`）、**Base URL**、**API Key**、**模型 ID**。四项对应快捷指令最前面的四个「文本」动作，之后点开文本框即可修改。
2. **绑定操作按钮**：设置 → 操作按钮 → 快捷指令 → 闪念。
3. **按一下，直接说话**：快捷指令先检查配置，通过后立即开始中文听写。模型 ID 留空时，听写前先从服务的 `/models` 列表里选一个模型。
4. **说完停顿一下，听写自动结束**：快捷指令把原话连同设备当地时间、时区发给配置的 AI 服务。
5. **自动分段、分类、写入**：AI 把一段话拆成多个事项，每项归入备忘录、提醒事项或日历，快捷指令按顺序写入。
6. **结果汇总**：全部写入成功时用一条通知汇总，例如「已处理 3 项」及每项去向。出现查询结果或改存、未执行的事项时，用弹窗展示完整内容。

结束听写：听写动作的「停止聆听」只有「停顿后」「短暂停顿后」「轻点」三种，没有「再按操作按钮」。iPhone 实测再次按操作按钮不能结束听写，所以现在设为「停顿后」，说完停一下就自动结束。想更快结束可改成「短暂停顿后」，想手动结束可改成「轻点」（在编辑器里点开「听写文本」动作修改）。

## 智能分类

| 内容 | 去向 | 说明 |
| --- | --- | --- |
| 在某个日期或钟点发生、需要到场的会议、约会、活动、行程 | 日历 | 即使口述说成「提醒我下午3点有会议」，会议本身也归日历。只给开始时间时按 1 小时记录并在备注注明；只有日期时创建全天事件 |
| 要自己去做的单件待办、提醒、截止事项（买一样东西、打电话、交材料等） | 提醒事项 | 有明确时刻时设置提醒时间；无日期为普通待办；只说日期没说钟点时，AI 给出默认到期时间：今天取当前时间之后的下一个整点，其他日期取当天 09:00，并在备注注明 |
| 想法、灵感、信息、清单，以及拿不准的内容 | 备忘录 | 兜底类别。要买、要带、要准备的东西有两样及以上（「去超市买可乐、橙汁和卷纸」）或说了「购物清单」，写成可勾选的待办项清单；同时说了时间（「明早八点去菜市场买…」）时另加一条提醒 |
| 明确要查找已有记录 | 对应 App 的真实查询 | 结果在本机展示 |

- **时间写设备当地时间**：AI 输出 `YYYY-MM-DDTHH:mm:ss`，不带时区偏移，由快捷指令按 iPhone 所在时区解释，夏令时也由系统处理。仍接受带 `Z` 或 `±hh:mm` 的值（按该时刻处理），缺秒数或用空格代替 `T` 的写法会先规整。只说了钟点没说日期（「下午3点有会议」）时，日期按今天。
- 日期说不准（「周末」「月底前」等）时，AI 改用备忘录或无日期待办，并把原话写进正文。
- 会议、约会、面试等说了日期或钟点，一律进日历并给出起止时间；只说「上午/下午/晚上」没有钟点时记为全天事件，正文写明原说法。「记一下」「对了」等开场白不单独成项。提示词附有完整示例，用户自己的模型直连实测见 `validation-mac-engine.log`。
- 日历的时间字段无法解析时，该项改存为备忘录，弹窗和备忘录正文里都会写出收到的原值。
- **提醒事项不会因为时间说法而失败**：「一会儿」「待会儿」等模糊说法，或任何无法识别的截止时间，都创建没有提醒时间的待办，并把原说法写进备注。
- **只说日期的提醒**（「今天交作业」「周五之前」）：Shortcuts 的新建提醒动作不能只设日期，所以由 AI 补一个默认时间——日期是今天就取当前时间之后的下一个整点，其他日期取当天 09:00——并在备注注明「未指定钟点，按默认时间设置」。这是默认值，不是你说的时间。
- 任一事项的日期、时间校验失败时，该项改存为备忘录并在正文注明原因，其余事项照常写入。
- 一次听写含多件事时，每项各自归类；每项正文保留该项的原话，多事项时不重复整段原话。

## 备忘录清单：可勾选的待办项

「水果、蔬菜和可乐」这类清单会写成一条备忘录：标题是清单名，每个条目是备忘录里一个可以点按勾选的待办项。流程：模型把 `checklist` 设为 `true` 并把条目按行写进 `body`；快捷指令先创建只有标题的备忘录，再逐行执行「追加待办项」。行首的 `-`、`*`、`•`、`☐` 等符号、空行和首尾空格会被去掉。

动作格式取自用户在 iPhone 上做的「创建备忘录 → 追加待办项」测试快捷指令的导出（该测试在 iPhone 上成功创建了可勾选的待办项）：

- 创建备忘录：`com.apple.mobilenotes.SharingExtension`，带 `AppIntentDescriptor`（`AppIntentIdentifier` = `CreateNoteLinkAction`，`BundleIdentifier` = `com.apple.mobilenotes`，`TeamIdentifier` = `0000000000`），输入键仍是 `WFCreateNoteInput`。
- 追加待办项：`com.apple.mobilenotes.CreateChecklistItemLinkAction`，参数 `name`（条目文字）和 `noteEntity`（指向创建备忘录动作的输出）。
- 全部 Notes 创建动作现在都带这个描述符。

Mac 引擎实测（测试版保留真实备忘录动作）：「西红柿、鸡蛋、- 青菜、空行、☐ 牛奶」写成一条备忘录，在「备忘录」App 里是 4 个能点按打勾、同一级的待办项。iPhone 上还没有端到端验证。

## 接入方式：API Key，两种协议

登录方式是 API Key。第一项配置选择协议：

| 协议 | 请求 | Base URL 怎么填 |
| --- | --- | --- |
| `openai`（OpenAI compatible） | `POST <Base URL>/chat/completions`，`Authorization: Bearer <Key>`，返回读 `choices[0].message.content` | 填到 `/v1` 这一级，例如 `https://api.openai.com/v1`；Anthropic 的 OpenAI 兼容端点填 `https://api.anthropic.com/v1` |
| `anthropic`（Anthropic compatible） | `POST <根地址>/v1/messages`，`x-api-key: <Key>`，`anthropic-version: 2023-06-01`，`system` 放顶层，`max_tokens` 为 4096；返回读第一个 `type` 为 `text` 的内容块（跳过 thinking 块） | 填服务根地址，例如 `https://api.anthropic.com`，或第三方网关的 `…/anthropic` 一级 |

Base URL 末尾多带 `/`、`/chat/completions`（openai）或 `/v1`、`/v1/messages`（anthropic）都会被规整，不会重复拼接。Azure OpenAI 这类需要 `api-key` 头或 `?api-version=` 的服务不在范围内。

**模型**：在第四项配置里手填模型 ID；留空则每次运行先请求服务的 `/models`（openai 协议为 `<Base URL>/models`，anthropic 协议为 `<根地址>/v1/models?limit=1000`），列出全部模型让你选一个。选中的 ID 填进最上方的「API Model」，以后就不再询问。`/models` 读取失败、没有返回列表时，停下并提示手动填写，且不开始听写。

回复里夹带的代码围栏或说明文字会被去掉，只取第一个 `{` 到最后一个 `}` 之间的内容，再按固定契约整体校验。

OAuth 登录未接入，原因如下：

- **Anthropic**：官方[法务与合规页](https://code.claude.com/docs/en/legal-and-compliance)规定，第三方产品通过 Claude Console 的 API Key 接入，不得提供 Claude.ai 登录，也不得用订阅凭据转发请求。
- **OpenAI**：[Sign in with ChatGPT](https://developers.openai.com/siwc/token-sharing-open-source) 为预览功能，面向开源和本地托管应用。流程要求应用在 `127.0.0.1` 开本地回环监听来接收回调，调用 Responses API，并保存会轮换的 refresh token。快捷指令无法开监听端口，也没有可靠的长期令牌存储。

## 「Please choose a value for each parameter in this action」：已修复（Mac 引擎实测）

用户在 iPhone 上创建日历事件、备忘录清单时得到这条系统报错；在 Mac 的 Shortcuts 引擎上，普通备忘录、日历（有时间、全天）、清单都在一个「如果」动作上报错，例如「如果 Checklist Flag 是 true」。

**根因**（Mac 引擎探针实测，见 `validation-mac-engine.log`）：「如果」做比较（是、不是、大于等需要比较值的条件）时，输入如果直接来自「获取词典值」——无论经不经过「设定变量」——引擎就认为比较值没填，报这条错。与字面量 `true`、布尔类型无关：字符串 `abc` 同样报错；先经过「文本」动作再比较则正常；「有任何值」不需要比较值，不受影响。

**修复**：三个标志（全天、含已完成、清单）先经「文本」动作再存入变量，与 `action` 等字段一致。JSON 布尔值经「文本」动作会变成「是」，所以合约校验后先把 `true`/`false` 改写成字符串，再取值。`test_value_sources_follow_what_the_mac_engine_accepts` 静态检查所有比较类「如果」的输入来源。

同一轮实测还发现并修复了三处不报错、但结果不对的问题：

- **格式化日期输出为空**：`WFDateFormat=Custom` 加 `WFDateFormatString` 的写法在引擎上输出空文本，发给模型的「设备当前时间」和时区因此是空的。现在按 Apple 原生导出，把格式串直接放在 `WFDateFormat`。
- **嵌套循环取错项**：清单逐行追加、三类查询逐条展示都在内层循环里，真实引擎的内层当前项叫「重复项目 2」（Repeat Item 2），原先引用的「重复项目」是外层的整条操作。
- **空文本「有任何值」为真**：到期时间为空的提醒走错分支；模型 ID 留空、标题为空、跳过空行等判断同理。现在统计非空白字符个数来判断。

日期值改由「日期」动作（指定日期）从校验过的文本生成；只有日期的值仍先补 `T00:00:00`，因为系统把纯日期解析成当天 12:00。

## 「API 返回错误」排查记录

用户在 iPhone 上填入正确的地址、模型和密钥后，运行得到「API 返回错误」。核对后发现上一版请求体与真实导出的快捷指令格式不一致：

- `messages` 数组里的字典元素 `WFItemType` 写成了 3。真实导出里 1 是字典、3 是数字（Shortcuts Playground 文档的类型表把 1 和 3 写反了，依据是其 golden 示例）。
- 字典元素的 `WFValue` 少包了一层 `WFDictionaryFieldValue`。
- 请求缺少真实导出里一直带着的 `Advanced: true`。

这三处会让系统发出残缺的 `messages`，服务端因此返回错误。现已按真实导出格式修正，并在离线解释器里加入类型码检查（`test_interpreter_rejects_item_types_that_real_shortcuts_would_mangle`）。**这一结论来自对照真实导出文件，尚未在 iPhone 上验证。**

之后任何 API 失败都会在弹窗里显示服务返回的错误原文、协议、请求地址和模型（不含 Key），以及响应开头 500 字符。

## 校验结果与遗留问题

- `plistlib` 读取实际交付 XML；`plutil -lint` 通过；1252 个动作，UUID 唯一，由本机 `uuidgen` 生成。
- 88 项离线测试通过，覆盖 JSON 契约、多事项循环、三类分类路由、失败改存、全天事件边界、配置接线（导入问题 → 请求地址、认证头、模型）、两种协议的请求头与请求体、Base URL 规整、/models 选模型及失败、错误原文显示且不泄露 Key、空配置与空听写、原话备份、查询边界，以及 Mac 引擎实测得到的取值规则。结果见 `offline-tests.log`。解释器是自建模拟器，不是 Apple Shortcuts 引擎；它已按实测改成：内层循环用「重复项目 2」、空文本也算「有值」、格式化日期只认原生写法。
- Mac 引擎实测：7 类写入场景通过；用真实备忘录动作的测试版写入普通备忘录、买菜清单和改存备忘录，备忘录查询能查回。
- 真实 API 端到端（openai 协议，用户自己的模型）：一句话里的日历、提醒、备忘录（含清单）各自拆成一项，分别写入三个 App，时间按设备时间换算正确，用户逐一确认。见 `validation-mac-engine.log`。
- **Shortcuts Playground 1.2.1 validator 整体仍失败**。最终日志见 `validation-ios27.log`、`validation-macos26.log`：
  - 19 处 Create Note 报「缺 title/name 参数」：插件按 macOS 的 `name` + `contents` 参数检查，而 iPhone 导出的动作只有 `WFCreateNoteInput`，所以是误报。iOS27 目标另把 Create Note 与 Find Notes 标为 macOS 专用，因为该插件的 iOS 快照不含任何 Notes 动作。
  - 1 处「未知 AppIntent 标识」：`com.apple.mobilenotes.CreateChecklistItemLinkAction`。插件只收录了 macOS 的 `com.apple.Notes.*` 标识，iPhone 导出样本里的标识是 `com.apple.mobilenotes.*`。
  - 3 处「文本为空」：对应 Base URL、API Key、模型 ID 三个导入问题的目标文本动作，内容在添加快捷指令时填写。插件自带的含导入问题的示例 `golden-shortcuts/xml/6a18b76843ac45c384ac3400f3740997.xml` 触发同一条检查。
  - 其余检查（控制流、变量连线、过滤器、日期动作、UUID）无报错。
- `validation-ios26.log` 使用 `--target-platform ios` 且不指定 macOS 版本；该插件仅有 iOS27 快照，基础动作也被目标规则拒绝，不能据此宣称 iOS26 兼容。
- Notes 动作格式以 iPhone 导出的样本为准：标题、空行、正文组成 `WFCreateNoteInput`，并带上述描述符。备忘录创建在 iPhone 上可用（用户反馈）。
- 签名方式和隐私说明见 `SIGNING.md`；文件大小和 SHA-256 见 `build-manifest.json`。

## 原话保护

- 配置里有一个「原话备份」文本，默认 `否`。改为 `是` 后，每次联网前先把原话存成备忘录「闪念原话 · 时间」，网络或权限中断时也能找回。
- 默认 `否` 时，API 返回错误、返回内容不合格式、空计划等能读取到的失败，会自动把原话存成备忘录「闪念原话（未处理）」并在弹窗里显示原话。
- 网络直接中断（离线、超时）时系统动作会终止快捷指令，此时仅在「原话备份」为 `是` 的情况下留有备忘录。

## 密钥与隐私

- 构建没有使用真实 API Key，没有读取个人笔记、日历、提醒事项或云备份，没有调用付费模型 API。XML 里 Base URL、API Key、模型 ID 三个配置文本为空，协议默认 `openai`。
- API Key 保存在你自己的这条快捷指令里，可能随 iCloud 同步。分享、导出或上传快捷指令之前先清空三项配置。
- 发送给自选 API 的是原话、设备当地时间和时区。认证 Key 通过请求 Authorization 头发送到同一提供方。数据保留、费用由该提供方决定。
- 本机查询到的笔记、日历和提醒记录仅在本机展示，不再发给模型。写入的备忘录、日历、提醒按 Apple App 的账户/iCloud 设置正常同步。
- 不要在原话中口述密码或密钥。
