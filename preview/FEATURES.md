# 闪念：签名测试版交付说明

此构建是供 iPhone 导入审查与实测的测试版，**不是各项能力均已验证的正式版**。源文件为 `ShanNian.xml`，目标名称为「闪念」。Apple 签名只证明文件成功封装签名，不证明动作能运行。

软件采用 [AGPL-3.0-or-later](../LICENSE)。下载版首条「注释」说明官方版本免费开源并附仓库地址；该文字仅在编辑器中展示，不是运行时提示，也不参与 API 请求。

## 使用流程

1. **添加时配置**：导入快捷指令时依次填写 AI 服务的 **Base URL**、**模型 ID**、**API Key**。三项对应快捷指令最前面的三个「文本」动作，之后点开文本框即可修改。
2. **绑定操作按钮**：设置 → 操作按钮 → 快捷指令 → 闪念。
3. **按一下，直接说话**：快捷指令先检查配置，通过后立即开始中文听写。
4. **说完点按屏幕上的完成**：快捷指令把原话连同设备当地时间、时区发给配置的 AI 服务。
5. **自动分段、分类、写入**：AI 把一段话拆成多个事项，每项归入备忘录、提醒事项或日历，快捷指令按顺序写入。
6. **结果汇总**：全部写入成功时用一条通知汇总，例如「已处理 3 项」及每项去向。出现查询结果或改存、未执行的事项时，用弹窗展示完整内容。

结束听写：听写动作的「停止聆听」设为「点按」（On Tap）。用操作按钮的**第二次按下**来结束听写，内置听写动作没有对应设置，需在 iPhone 上实测。想要停顿后自动结束，把听写动作的「停止聆听」改为「停顿后」。

## 智能分类

| 内容 | 去向 | 说明 |
| --- | --- | --- |
| 有明确日期（可带时间）的会议、约会、活动、行程 | 日历 | 只给开始时间时按 1 小时记录并在备注注明；只有日期时创建全天事件 |
| 要自己去做的待办、提醒、截止事项 | 提醒事项 | 有明确时刻时设置提醒时间；无日期为普通待办；仅日期时创建无提醒时间的待办，日期写在备注 |
| 想法、灵感、信息、清单，以及拿不准的内容 | 备忘录 | 兜底类别 |
| 明确要查找已有记录 | 对应 App 的真实查询 | 结果在本机展示 |

- 日期说不准（「周末」「月底前」等）时，AI 改用备忘录或无日期待办，并把原话写进正文。
- 任一事项的日期、时间校验失败时，该项改存为备忘录并在正文注明原因，其余事项照常写入。
- 一次听写含多件事时，每项各自归类；每项正文保留该项的原话，多事项时不重复整段原话。

## 能力表

| 操作 | 已实现及静态检查覆盖 | 已实现、仍未验证 | 限制 |
| --- | --- | --- | --- |
| `note.create` | 标题与正文组合为一个输入；标题为空时用时间作标题；也是其他类别校验失败时的改存目标 | legacy `com.apple.mobilenotes.SharingExtension` + `WFCreateNoteInput` 在 iPhone 的识别与创建结果；插件整体校验未通过 | 所有备忘录写入依赖这个动作 |
| `note.search` | 名称 OR 正文关键词过滤；最多 10 条；正文最多 1200 字符；缺关键词时不读取记录 | iPhone Notes 权限、过滤属性与正文读取；插件把此动作标成 macOS 专用 | 不做语义搜索，不把查得笔记交给模型 |
| `calendar.create` | 起止时刻校验、结束晚于开始、全天事件只含日期；失败改存备忘录 | 时区、夏令时、全天事件结束日（按「系统包含最后一天」处理）、目标日历选择 | 无自动指定日历；地点保留在备注 |
| `calendar.search` | 结束日期下界、可选标题关键词、开始时间排序；最多 10 候选；上界排他；保留跨界重叠事件 | 系统过滤与权限行为 | 一次范围最多 31 天（容许一次夏令时切换） |
| `reminder.create` | 无日期待办、明确时刻提醒、仅日期待办（无提醒时间，日期写在备注）；格式不符改存备忘录 | 默认列表、具体时刻与通知行为 | 不指定自定义列表；仅日期时没有系统级截止日期 |
| `reminder.search` | 默认未完成；用户明确要求才含已完成；可选范围与标题词；最多 10 条；上界排他 | 完成状态、截止日期属性、列表名称和权限 | 无日期范围时返回最多 10 条；不自动分页 |

“静态覆盖”仅指源结构、离线契约与模拟动作流检查，不代表完整 Shortcuts Playground 校验通过或 Apple 真机测试通过。

## 接入方式：API Key

接入方式是 OpenAI-compatible Chat Completions 协议 + Base URL + API Key。OAuth 登录未接入，原因如下：

- **Anthropic**：官方[法务与合规页](https://code.claude.com/docs/en/legal-and-compliance)规定，第三方产品通过 Claude Console 的 API Key 接入，不得提供 Claude.ai 登录，也不得用订阅凭据转发请求。
- **OpenAI**：[Sign in with ChatGPT](https://developers.openai.com/siwc/token-sharing-open-source) 为预览功能，面向开源和本地托管应用。流程要求应用在 `127.0.0.1` 开本地回环监听来接收回调，调用 Responses API，并保存会轮换的 refresh token。快捷指令无法开监听端口，也没有可靠的长期令牌存储。

## 校验结果与遗留问题

- `plistlib` 读取实际交付 XML；`plutil -lint` 通过；1050 个动作，UUID 唯一，由本机 `uuidgen` 生成。
- 40 项离线测试通过，覆盖 JSON 契约、多事项循环、三类分类路由、失败改存、全天事件边界、配置接线（导入问题 → 请求地址、认证头、模型）、空配置与空听写、原话备份、查询边界。结果见 `offline-tests.log`。解释器是自建模拟器，不是 Apple Shortcuts 引擎。
- **Shortcuts Playground 1.2.1 validator 整体仍失败**。最终日志见 `validation-ios27.log`、`validation-macos26.log`：
  - 15 处 Create Note 缺 `AppIntentDescriptor` 及独立 title/name 参数（同一生成函数写出，修复时只需改一处）；iOS27 目标另把它与 Find Notes 标为 macOS 专用。该插件的 iOS 快照不含任何 Notes 动作，没有可用的 iOS 格式依据。
  - 3 处「文本为空」：对应三个导入问题的目标文本动作，内容在添加快捷指令时填写。插件自带的含导入问题的示例 `golden-shortcuts/xml/6a18b76843ac45c384ac3400f3740997.xml` 触发同一条检查。
  - 其余检查（控制流、变量连线、过滤器、日期动作、UUID）无报错。
- `validation-ios26.log` 使用 `--target-platform ios` 且不指定 macOS 版本；该插件仅有 iOS27 快照，基础动作也被目标规则拒绝，不能据此宣称 iOS26 兼容。
- Notes 的格式问题仍需 iPhone 实际导入结果或匹配目标 iOS 的真实导出作为依据。保留具有公开 iOS 工具映射依据的 legacy 输入键：标题、空行、正文组成 `WFCreateNoteInput`。
- 签名方式和隐私说明见 `SIGNING.md`；文件大小和 SHA-256 见 `build-manifest.json`。

## 原话保护

- 配置里有一个「原话备份」文本，默认 `否`。改为 `是` 后，每次联网前先把原话存成备忘录「闪念原话 · 时间」，网络或权限中断时也能找回。
- 默认 `否` 时，API 返回错误、返回内容不合格式、空计划等能读取到的失败，会自动把原话存成备忘录「闪念原话（未处理）」并在弹窗里显示原话。
- 网络直接中断（离线、超时）时系统动作会终止快捷指令，此时仅在「原话备份」为 `是` 的情况下留有备忘录。

## 密钥与隐私

- 构建没有使用真实 API Key，没有读取个人笔记、日历、提醒事项或云备份，没有调用付费模型 API。XML 里三个配置文本为空。
- API Key 保存在你自己的这条快捷指令里，可能随 iCloud 同步。分享、导出或上传快捷指令之前先清空三项配置。
- 发送给自选 API 的是原话、设备当地时间和时区。认证 Key 通过请求 Authorization 头发送到同一提供方。数据保留、费用由该提供方决定。
- 本机查询到的笔记、日历和提醒记录仅在本机展示，不再发给模型。写入的备忘录、日历、提醒按 Apple App 的账户/iCloud 设置正常同步。
- 不要在原话中口述密码或密钥。

## iPhone 导入与验收

通过隔空投送或 iCloud Drive 在 iPhone 打开 `ShanNian.shortcut`，依次填写 Base URL、模型 ID、API Key，审查动作后添加。先在快捷指令 App 内运行一次，系统权限按需授权；再到「设置 → 操作按钮 → 快捷指令 → 闪念」绑定。

建议使用无敏感信息的测试数据，并逐项检查：

- [ ] **首先检查所有「创建备忘录」「查找备忘录」动作有无未知动作。**
- [ ] 导入时出现三个问题；添加后快捷指令最前面是三个已填写的文本动作，修改后立即生效。
- [ ] 配置留空时，运行会提示去最上方填写，且不开始听写。
- [ ] 按操作按钮立即开始听写；记录用操作按钮第二次按下能否结束听写。
- [ ] 一句话里的三件事：「明天下午三点到四点见导师，提醒我周五之前买洗衣液，还有我想把操作按钮做成灵感入口」应得到日历、提醒、备忘录各一条，通知汇总三项。
- [ ] 只说日期的事项：全天事件的起止日在日历里显示正确（单日、多日）；「周五之前」的提醒是无提醒时间的待办，日期在备注。
- [ ] 说不准的时间（「周末有个会」）：改存为备忘录，正文保留原说法。
- [ ] 夏令时日、跨午夜、跨时区的日历事件。
- [ ] note.search：用测试笔记的独特关键词检索；另一随机词应明确没有找到。calendar.search、reminder.search 的边界与空结果。
- [ ] 模型返回缺字段、错误类型、未知 action 时没有目标创建，原话被保存。
- [ ] 401/额度不足、HTML 响应、离线、拒绝 Calendar/Reminders 权限：核对原话备份开关两种取值下的结果。
- [ ] 听写为空时的提示；拒绝麦克风权限后重新运行。

本机只完成构建、静态/离线检查和签名；**没有执行这些 iPhone 验收测试，也没有验证真实 API 响应或系统写入。**

## 依据与重建

- 本仓库构建要求：`../ci/BUILD_LOCAL_PROMPT.md`、`../spec/闪念_Shortcuts_构建规格.md`。
- 安装的 Shortcuts Playground 1.2.1：在已有插件或参考源中查找包含 `SKILL.md` 和 `scripts/` 的技能目录。导入问题格式参照其 golden 示例（`ActionIndex`、`Category`、`ParameterKey`、`Text`、`DefaultValue`）。
- legacy iOS Create Note 输入键：[作者 Shortcut Source Tool 动作映射](https://github.com/extratone/jellycuts/blob/main/ShortcutsBatchSource.jelly#L539-L543)。这是工具映射依据，不是当前 iPhone 导出实例。
- HTTP 请求参照 [Chat Completions 官方文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。

生成器：`python3 preview/build_shannian.py`；离线检查：`python3 -m unittest discover -s preview -p 'test_*.py' -v`。重新生成 XML 后须重新静态校验并签名，旧签名不会自动更新。签名时输入文件使用 `.shortcut` 扩展名和与快捷指令同名的文件名（如 `ShanNian-sign-input.shortcut`），并在沙箱外执行 `shortcuts sign`。仓库跟踪 `preview/` 中的测试版快照与可重建源文件。本机临时构建目录 `dist/` 被 Git 忽略。未包含本机凭据或个人数据库。
